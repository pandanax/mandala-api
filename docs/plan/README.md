# Единый план развития Mandala

> Приоритизированный план, сводящий воедино roadmap.md, тикет кнопок/команд,
> TODO из кода и недоделки из веток. Последнее обновление: 2025-07 (ветка `gnhf-night`).
> Исторические тикеты 1–24 — в [implementation-plan.md](../implementation-plan.md).

## Цель продукта

Удобный, настоящий **астролог-бот** для людей, серьёзно увлечённых астрологией.
Кнопки-транзиты и подменю прогнозов удерживают пользователя («retention-петля»).
Бот знает западную и ведическую системы, считает математически, интерпретирует через LLM.

## Приоритет 1 — Качество астро-ядра (удержание)

### 1.1. Промпты вертикали `astrology` ⬡ сделать глубже
**Цель:** Системный промпт сейчас базовый. Нужен промпт астролога-профессионала.
**Объём:**
- Расширить `verticals/prompts.py`: добавить контекст о поддерживаемых системах, домах, аспектах
- Добавить инструкции по форматированию: как давать интерпретации, что включать в прогноз
- Разделить промпты: natal / synastry / forecast (можно через LLM_VERTICAL_OVERRIDES_PATH)
**Критерии:** Ответы бота читаются как настоящий астрологический разбор, не как заготовка
**Зависимости:** docs/astrology/foundations.md (уже в прогрессе), KB в `verticals/kb/astrology/`

### 1.2. KB астрологии — реальный контент ⬡ нужно сделать
**Цель:** RAG-база знаний с реальным астрологическим контентом, не demo.md
**Объём:**
- Файлы `src/mandala/verticals/kb/astrology/*.md`: планеты, знаки, дома, аспекты, управители
- Контент для западной системы (тропик, Placidus), контент для ведической (накшатры, даши)
- Источники и проверка фактов — см. [docs/astrology/sources.md](../astrology/sources.md)
**Критерии:** `python -m mandala.index_kb --vertical astrology` индексирует содержательные тексты
**Зависимости:** 1.1, Qdrant в проде

### 1.3. Прогнозы/транзиты с реальными позициями ⬡ нужно сделать
**Цель:** «Прогноз на сегодня» должен использовать текущие позиции планет (транзиты), не только натальные
**Объём:**
- Функция `calculate_transits_now()` в `astro/natal_chart.py`: позиции на текущую дату
- Функция сравнения транзит–натал: аспекты между текущими позициями и натальными
- Передача транзитных данных в промпт (`text_reply.py`)
- Тесты для новой математики
**Критерии:** При нажатии «📅 Сегодня» LLM получает текущие позиции планет + аспекты к натальным
**Зависимости:** 1.1, работающая натальная математика (уже есть)

### 1.4. Синастрия (совместимость) ⬡ нужно сделать
**Цель:** Пользователь вводит данные второго человека → разбор совместимости
**Объём:**
- Новый сценарий `intake_steps.json["astrology_synastry"]` (имя, дата, место, время)
- Функция `calculate_synastry(subject1, subject2)` в `astro/natal_chart.py`
- Роутинг: кнопка `mdl:syn` → подменю «ввести данные партнёра» или «у меня уже есть»
- Хранение второй карты в `agent_card["synastry_partner"]`
**Критерии:** Полный разбор совместимости с реальными аспектами между двумя картами
**Зависимости:** 1.1, 1.3

## Приоритет 2 — UX и retention

### 2.1. ✅ DONE: Кнопки-транзиты (retention-петля) — реализовано
**Что сделано:**
- Reply-клавиатура: «🔮 Натальная карта», «📊 Прогноз», «👤 Профиль», «🔄 Начать заново»
- Inline-подменю прогноза: Сегодня, Неделя, Месяц, Год
- Все callback_data роутируются через `quick_actions.expand_inbound_quick_action()`
- `answerCallbackQuery` вызывается при каждом нажатии кнопки
- URL-кнопки в outbound корректно сериализуются (не подменяются на callback_data)
- Web-канал: `callback_data` принимается, `buttons` попадают в JSON-ответ
- bash scripts/check.sh зелёный

### 2.2. ✅ DONE: Команды (/help, /about, /reset, /promo) — реализовано
Работают до и после анкеты, включая `setMyCommands` через `bot_commands.py`.

### 2.3. Per-vertical контент в БД (`agent_verticals.config.ui`) ⬡ нужно сделать
**Цель:** Тексты приветствия/about можно менять без релиза через UPDATE в БД
**Объём:**
- Новая миграция: расширить `agent_verticals.config` полем `ui` (JSONB):
  ```json
  { "ui": { "welcome_text": "...", "about_text": "...", "default_buttons": [...] } }
  ```
- `VerticalConfigRepository` с кэшем на процесс
- Фоллбэк на зашитые строки при отсутствии БД-конфига
- Seed UI-текстов для `astrology` в миграции
**Критерии:** UPDATE в БД без деплоя меняет тексты
**Зависимости:** Понимание хорошего UX-текста (после 1.1)

### 2.4. Профиль пользователя — визуализация карты ⬡ нужно сделать
**Цель:** `mdl:profile` показывает полный красивый профиль с ключевыми позициями
**Объём:**
- Форматирование `_handle_show_profile()`: планеты с символами знаков, аспекты, дома
- Возможно: генерация простой SVG-карты (колесо зодиака)
**Критерии:** Пользователь видит красивое резюме своей натальной карты
**Зависимости:** 1.1

## Приоритет 3 — Инфраструктура и надёжность

### 3.1. RAG в проде (Qdrant) ⬡ нужно настроить
**Цель:** RAG работает на продовом сервере
**Объём:**
- Запустить Qdrant на VM (через Docker/systemd)
- `MANDALA_RAG_BACKEND=qdrant`, `QDRANT_URL` в env
- Индексация: `python -m mandala.index_kb --vertical astrology`
- Документация обновления KB без полного редеплоя
**Критерии:** LLM-ответы используют RAG-контекст
**Зависимости:** 1.2 (реальный контент KB)

### 3.2. Мониторинг и алерты ⬡ нужно сделать
**Цель:** Оповещения при проблемах с API, БД, LLM, webhook
**Объём:**
- Базовые метрики: uptime `/health`, latency LLM, ошибки webhook
- Telegram-алерт при падении (простой cron + curl)
- Опционально: Yandex Monitoring / Grafana
**Зависимости:** Нет (независимо)

### 3.3. Terraform remote state (Yandex Object Storage) ⬡ нужно сделать
**Цель:** Несколько человек / машин безопасно работают с инфрой
**Объём:** — см. docs/implementation-plan.md тикет 24
**Зависимости:** Тикет 23 (выполнен для MVP)

### 3.4. Секреты в Lockbox ⬡ нужно сделать
**Цель:** Секреты не «вечным файлом на диске»
**Объём:** — см. docs/implementation-plan.md тикет 24
**Зависимости:** Нет

### 3.5. Web-канал: авторизация ⬡ нужно сделать
**Цель:** `Authorization: Bearer` → `vertical_id` вместо заголовка `X-Vertical-Id`
**Объём:** Таблица API-ключей → vertical_id + middleware в `mandala.http`
**Зависимости:** Нет
