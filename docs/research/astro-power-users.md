# Исследование: продвинутые астро-пользователи

> Что удерживает серьёзных любителей астрологии, чего они ждут от бота-астролога.
> Связь с дизайном retention-петли кнопок-транзитов.

---

## Кто такой «продвинутый астро-пользователь»

**Портрет:** человек, который:
- Знает свой знак Солнца **и** знак Луны **и** Асцендент
- Использует хотя бы одно астро-приложение (Astro.com, Time Passages, Astroseek, Co-Star, Chani)
- Знает понятия «аспекты», «транзиты», «дома», «ретроградный Меркурий»
- Периодически следит за текущими планетарными позициями
- Возможно, читает Liz Greene, Robert Hand или ведических авторов

**Что они НЕ хотят:**
- Гороскоп по одному знаку Солнца («гороскоп Стрельца на неделю»)
- Развлекательный контент, не основанный на карте
- Поверхностные обобщения («Марс — энергия, Венера — любовь»)

## Что удерживает продвинутых пользователей

### 1. Персонализация по полной карте
Ключевое отличие от масс-гороскопов: прогноз строится по **реальной карте** пользователя.
«Юпитер сейчас в 2° Тельца, и он стоит точно на твоей натальной Луне в 1° Тельца — это
значит...» — это и есть то, за чем приходят. [TODO: проверить типичный пример, 2025]

### 2. Транзитный календарь
Регулярные короткие проверки: «что происходит с моей картой прямо сейчас/на этой неделе».
Именно это создаёт привычку возвращаться ежедневно или несколько раз в неделю.

Аналоги в существующих приложениях:
- **The Pattern** (iOS, ~5M users): ежедневные «моменты» на основе транзитов, уведомления
- **Co-Star** (iOS, ~20M users): ежедневные push-уведомления с транзитным прогнозом
- **Chani** (iOS): расширенные объяснения, подписка ~$30/год

### 3. Глубина тематических разборов
Разбор конкретной сферы жизни: «как моя карта говорит о деньгах», «что у меня с отношениями».
Не общий разбор, а тематический — по релевантным домам и управителям.

### 4. Синастрия с конкретным человеком
Один из самых запрашиваемых типов разборов — особенно в романтическом контексте.
Требует данных обоих партнёров.

### 5. «Понять, почему так» — объяснения
Продвинутый пользователь хочет **понять логику**, а не просто получить предсказание.
«Почему я чувствую себя так этим летом?» → «Сатурн транзитом квадратует твоё натальное Солнце...»

### 6. Ведическая аудитория
Отдельный сегмент — интересующиеся Джйотиш. Ищут:
- Накшатру Луны
- Свою Маха-дашу / Антар-дашу
- Совместимость по гуна-милану
- Мухурту (выбор благоприятного времени)

## Что должен уметь бот для этой аудитории

### Must-have (retention-петля)
1. ✅ **Натальная карта по данным рождения** — уже есть
2. ✅ **Кнопки прогнозов** (сегодня/неделя/месяц/год) — уже есть (без реальных транзитов)
3. ⬡ **Реальные транзиты в прогнозах** — нужно реализовать (см. forecasting-transits.md)
4. ⬡ **Ежедневные уведомления** — потенциальный killer feature

### Should-have
5. ⬡ **Синастрия** — очень запрашиваемая фича
6. ⬡ **Объяснение карты по домам** — тематические разборы (частично есть)
7. ⬡ **Ведическая система** — отдельная аудитория

### Nice-to-have
8. ⬡ **Мухурта** — выбор благоприятного времени для события
9. ⬡ **Солярный возврат** — карта для конкретного года жизни
10. ⬡ **Прогрессии** — продвинутый прогностический метод

## UX/кнопочный дизайн для retention

Текущая клавиатура уже хорошая. Следующий уровень:

```
Главная клавиатура (Reply Keyboard):
[🔮 Натальная карта]  [📊 Прогноз]
[👤 Профиль]           [🔄 Начать заново]

Подменю «📊 Прогноз» (Inline):
[📅 Сегодня]   [📆 Неделя]
[🗓️ Месяц]     [🔭 Год]

После натальной карты (Inline):
[💰 Финансы]    [❤️ Отношения]
[⚡ Здоровье]   [👫 Совместимость]
[🔄 Обновить карту]

Раздел совместимости (будущее):
[Мой партнёр]  [Ввести данные]
```

**Ключевой UX-принцип:** пользователь должен ВСЕГДА видеть, на какую дату/период
относится прогноз, и понимать, что бот использует его реальную карту — не общий гороскоп.

Формулировки типа:
> «📅 Прогноз на 25 июля 2025 по твоей карте (транзиты к натальным позициям):
> Юпитер трин натальной Луне — хороший день для планирования...»

создают доверие и удержание, в отличие от:
> «Сегодня хороший день для Стрельцов...»

## Выводы для продукта

1. **Главный приоритет** — реальные транзиты в прогнозах (сейчас LLM «угадывает» без данных)
2. **Удержание** — транзитный прогноз «на сегодня» должен быть ежедневным поводом вернуться
3. **Глубина** — синастрия и тематические разборы создают повторные сессии
4. **Доверие** — явные ссылки на Swiss Ephemeris и реальную математику важны для аудитории
5. **Честность** — бот должен указывать когда точность снижена (нет времени рождения → нет Асцендента)
